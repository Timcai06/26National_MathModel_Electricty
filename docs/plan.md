## 协作与依赖解释

以下顺序约束正式阶段执行与验收，不要求 tim、A、B 串行等待。tim 先做符号、假设、接口和模型推导；A 加工数据，B 独立检查原始输入后再交叉核验。模型代码与结果由 tim 统一掌握。

Phase 0 中 SOC 双解释和两种 PV 转换的成本比较拆成“本阶段明确方法和实验协议、具备内核及相应回测后执行比较”。不在 Phase 0 求解正式优化，也不删除后续比较任务。Gate 0 的数据、索引和测试要求保持不变；五份真实模板已找到，但时间/输出映射尚未冻结，不能通过完整 Gate 0。

## 阶段计划

### Phase 0：数据契约与题意冻结

- **目标**：在优化前冻结数据、日期、时间、单位、输出映射和题意解释，消除会导致整题返工的歧义。
- **任务**：建立 144-slot 唯一时间轴；核验附件 1–4 与官方结果模板；修复附件 3 日期语义；实现小时级光伏预测到 10 分钟的分段常数和分段线性转换，并设计两者的成本影响比较；统一 kW→kWh；明确 Q3 调整计费与 Q4 价格可知性；制定防未来数据泄漏规则；保留 Daily-neutral 与 Cross-day 两种终端 SOC 解释，并设计成本、每日终端 SOC 和 horizon effect 的双模型审计。
- **阶段产物**：`DATA_AUDIT.md`、`TIME_AXIS_AUDIT.md`、`MODEL_ASSUMPTIONS.md`、处理数据摘要、数据加载与时间轴实现、时间轴及防泄漏测试。文档分别归档到 [data](data/README.md)、[model](model/README.md) 和 [validation](validation/README.md)。
- **依赖**：真实附件、题面和官方模板；无上游阶段。
- **Gate 0**：365×144 数据读取正确；附件 3 重建为 365×4×24；非预期缺失为零；输入、模型、输出索引一一映射；日期、时间、功率/电量转换有自动化测试。
- **状态**：核心标准化数据数值通过；Q3转换已完成。时间/观测/计费契约与队友可复现材料尚待补齐，Gate 0未最终放行。

### Phase 1：统一储能与能量平衡内核

- **目标**：建立 Q1–Q4 共用的物理约束内核。
- **任务**：实现能量平衡、SOC 转移与边界、充放电功率上限、非负购电、弃光、可开关紧急购电和可配置终端 SOC；先采用 LP，检测到同时充放电后再评估 MILP。
- **阶段产物**：统一约束构建器、能量平衡与电池约束测试、同时充放电诊断记录。
- **依赖**：Gate 0。
- **Gate 1**：能量残差、SOC、充放电上限、终端条件和非负购电测试全部通过。
- **状态**：数学设计已形成，见[公共储能内核](model/MICROGRID_CORE.md)；约束构建器已实现，物理功能通过[合成技术验证](validation/CORE_Q1_SYNTHETIC.md)；整体阶段接收仍依赖Gate 0及假设冻结。

### Phase 2：问题 1 确定性日前优化基线

- **目标**：用附件 1 跑通求解、验证、图表和 Excel 输出闭环。
- **任务**：比较无储能、规则调度和优化调度；检查经济直觉；绘制负载/光伏/购电、充放电、SOC、电价联动图；生成候选结果文件且不覆盖模板。
- **阶段产物**：Q1 三类策略结果、核心图、论文表格数据、`result1_candidate.xlsx`。
- **依赖**：Gate 1。
- **Gate 2**：求解成功；物理残差与 SOC 合规；144 个时间片完整回填；论文数据可自动抽取；优化模型优于至少一个简单基线。
- **状态**：真实Q1三策略、表格、图及候选Excel完成；时间与模型语义待接收，Gate 2未最终通过。

### Phase 3：问题 2A 严格因果预测

- **目标**：明确每天 0:00 可用信息，并建立无未来数据泄漏的负载与光伏预测引擎。
- **任务**：以 1 月作初始化窗口、2 月 1 日起评价；实现昨日/上周同时刻等基线；按 walk-forward 或 expanding-window 训练；分别评价负载和光伏误差。
- **阶段产物**：预测基线与候选模型、逐日回测结果、MAE/RMSE 及分时诊断、无泄漏证据。
- **依赖**：Gate 2 和 Phase 0 的信息契约。
- **Gate 3**：主模型稳定优于至少一个朴素基线，或预测误差改善有限但下游购电成本显著降低；否则保留更简单模型。
- **状态**：真实历史基线已运行；只用1月选择负荷上周/PV昨日，2—12月固定，费用优于昨日基线。技术证据完成；可用时刻仍为候选，正式Gate 3未验收。

### Phase 4：问题 2B 风险感知日前调度

- **目标**：将优化目标从单纯预测精度转为含 5 倍紧急购电惩罚的决策成本。
- **任务**：建立点预测确定性策略与基于历史残差场景的风险策略；比较 Oracle、朴素预测、机器学习点预测和风险优化；在内核和回测可用后落实 Phase 0 登记的终端 SOC 双模型与两种 PV 转换成本比较；分解正常与紧急购电成本并计算 Oracle Regret。
- **阶段产物**：全年策略对比、成本分解、紧急购电与弃光指标、风险模型保留或回退结论。
- **依赖**：Gate 3。
- **Gate 4**：风险模型降低全年总成本，或以可解释的成本代价显著减少紧急购电；否则回退到简单策略。
- **状态**：真实Q2基础确定性策略、1月连续热身及334天结算完成。风险场景优化未实现，不能按完整风险阶段宣布Gate 4通过。

### Phase 5：问题 3A 滚动优化 MPC

- **目标**：将日前计划升级为 0:00、6:00、12:00、18:00 的滚动重优化。
- **任务**：锁定已发生时段；继承真实执行后的 SOC；只使用当时已发布的预测；相对 `current_commitment` 逐次计算增购/减购成本；测试另一种计费解释作为敏感性版本。
- **阶段产物**：滚动优化器、承诺量状态记录、调整成本明细、SOC 连续性与无泄漏测试。
- **依赖**：Gate 4 和附件 3 的 Phase 0 数据契约。
- **Gate 5**：过去时段不可修改；滚动时刻 SOC 连续；调整费用不重复；新计划只影响未来；所有成本可逐项还原。
- **状态**：Q3线性/常数预报转换、当日剩余时段MPC及逐次合同账本完成，334天真实执行与独立核验通过。基础技术条件有证据，观测/计费/输出语义待最终接收。

### Phase 6：问题 3B 预测信息价值 VOI

- **目标**：用预测改善收益与调整合同成本的差额判断是否值得更新计划。
- **任务**：比较仅 0:00、逐步加入 6/12/18 点及自适应 VOI 五类策略；统计总成本、调整成本、紧急购电、调整次数和边际节约。
- **阶段产物**：各发布时间 VOI 结果、固定滚动与自适应策略对比、Q3 经济结论。
- **依赖**：Gate 5。
- **Gate 6**：使用全年数据回答 6:00、12:00、18:00 是否值得调整，以及固定四次滚动与自适应 VOI 谁更优。
- **状态**：已比较单次6/12/18、三次更新、旧预报控制，回答固定策略的实际费用差异；自适应VOI尚未实现，Gate 6未完整通过。
