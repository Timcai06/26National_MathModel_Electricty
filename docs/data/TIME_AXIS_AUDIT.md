# 144 槽时间轴审计与候选映射

版本：endpoint-positional-v0.1-candidate，2026-09-11。执行者：tim 的 AI 助手。本轮完成时间轴实现、真实标签全量核对和测试；候选物理解释仍需独立交叉核验，不代表完整 Gate 0 通过。

## 结论与选择依据

四套输入轴都按 `00:10, 00:20, …, 23:50, 0:00+1` 排列，每套144个位置。若解释为区间终点，位置0对应 `[00:00,00:10)`，位置143对应 `[23:50,次日00:00)`，覆盖题面定义的0:00–24:00。

七套计划/调整输出轴从 `0:10–0:20` 开始。按显示标签原意，它们覆盖00:10至次日00:10，与上述模型日整体偏移10分钟。不能同时声称“模型覆盖0:00–24:00”和“每个输出原标签都与对应物理区间一致”。

因此当前采用**供审阅的候选映射**：内部按区间终点解释输入，以原位置保留数据和输出索引；保留官方标签，不重命名、不循环移位、不假装标签和物理区间一致。源计划本来就要求优先保留官方位置，本轮将其落实为可追溯表，但不是官方勘误结论。

另一个“输入为区间起点”的解释也可显式构造，模型范围为00:10–次日00:10；这会缺失本日最初10分钟、包含次日最初10分钟，不能直接用于0点与24点SOC约束。若未来按输出字面区间重构模型，必须同时重审跨日数据、承诺范围、SOC边界及论文时间段，不能只把输出移一格。

## 状态边界与滚动时刻

内部采用144个动作槽和145个状态边界：`E[0]`为当日0点，`E[144]`为次日0点。每个槽更新一次储能状态；不把最后一个动作误作第145个动作。

候选解释下，0/6/12/18点的未来完整槽分别从0/36/72/108开始；6点以前的36个动作已锁定。若在06:05调用，06:00–06:10已开始，该函数只返回06:10以后的完整槽，不允许回写已开始槽；题目固定整点决策不需要部分槽切分。

所有datetime包含Asia/Shanghai时区。跨日标签保留日偏移，绝不把 `0:00+1` 与本日 `0:00` 合并。
