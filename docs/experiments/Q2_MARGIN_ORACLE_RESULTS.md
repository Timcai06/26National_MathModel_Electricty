## 裕量的冻结与因果性

沿用已确定的负荷上周同时刻、光伏昨日同时刻预测；不更改原数据。定义过去某日净负荷残差为实际净负荷减去当时滞后预测的净负荷。只取目标日前已完整发布的日期，且该残差对应预测的源数据在当日零点已经可用。

固定6个4小时桶，每桶合并过去28日内对应的10分钟残差，至少有7个完整残差日才启用。校正量是 `scale * max(0, quantile(raw_residual, tau))`，加到预测负荷上，光伏预测不变。这是购电风险裕量，不宣称无偏预测；不再额外加均值偏差。

运行前记录9个候选：零裕量，以及 `tau∈{0.6,0.7,0.8,0.9}` × `scale∈{0.5,1}`。1月8—14日形成首批7日残差，1月15—31日按当时已有历史逐日回放，以B0执行器的实际总费用选参数。选择函数仅接收一月数据；实际库不足时回退零裕量，不用未来补齐。

## Oracle边界

两个Oracle均保持初末6000、1200—10800能量界、母线侧5000 kW、各方向0.9、充放互斥、无售电、相同普通/应急电价。仅放宽信息：零点知道目标日实际负荷/PV。

- `B0 − fixedGOracle = 2,364,317.74元`：固定原购电量时，完美信息调度比B0少花的费用，是理论空间，不保证因果策略能实现。
- `fixedGOracle − fullOracle = 1,972,178.87元`：在这两种完全信息基准之间，允许重新优化日前购电量的差异。
- `B2 − fullOracle = 2,892,940.14元`：B2距离同约束理想下界的差距。不能把固定原G的Oracle当作B2自身固定G的下界，因为B2的合同已改变。

逐日核对 `fullOracle ≤ fixedGOracle ≤ B0/B1`，以及 `fullOracle ≤ B2/B3`，334天均通过。求解接口仅接收通过独立物理检查的最优状态；Oracle绝不写入可执行策略或官方结果Excel。
