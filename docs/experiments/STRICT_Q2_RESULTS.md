## 能解释什么

独立重算冻结预测下的应急量，B0/B1均无超过1e-6 kWh的应急槽。也就是说，在确定性预测目标上两者都已达到零应急下界；不同充放电安排在真实预测误差下产生不同费用。本轮没有日内预测修正，实际净负荷不改变预先指定动作所决定的SOC，因此不能把这3.07万元解释为获得新实际信息的反馈收益。

每天最后6/12/24槽应急量，B0约为31007.38 / 63451.88 / 127899.47 kWh，B1几乎相同。当前证据不支持“小时MPC明显消除了日终恢复应急”。这些是末段应急统计，不能严格归因于日终目标。

旧同槽反馈Q2候选总费15,438,615.10元。新B0高出1,142,928.43元，属于改变信息/执行口径后的差异，不能当作同口径算法退化。旧费用及Excel均保留。

## 实现和复核

- 新执行器：`src/q2/strict_execution.py`。`decide`不接收实际值；`settle`必须在动作锁定后调用，且不能修改动作。预报只能在零点前可用；每槽记录指令时间、所属小时计划时间与最新已结束槽。
- B1每小时求解一次、每次执行6槽，保持日终6000、各方向0.9、母线侧5000 kW及5倍应急。复用公共LP/MILP内核，不改原同槽执行器。
- 求解器边界浮点误差通过指令投影处理，最大允许校正1e-6 kWh量级，边界内缩1e-8 kWh；SOC始终由执行的充放电计算，不直接覆盖状态。
- 两策略分别执行1月31天初始化，Jan1零购电且无历史预测；Jan2–31昨日预测。两者1月费均约2,838,194.22元，不计入正式334天费用；每日终端6000并逐日继承实际状态。
- 运行命令 `rtk proxy .venv/bin/python scripts/run_strict_q2.py` 成功；完成版本拒绝覆盖，重跑需显式另设版本目录。正式期执行器耗时不含共同日前求解，总运行约19秒。
- `rtk proxy .venv/bin/python scripts/verify_strict_q2.py` 退出0：730条日轨迹、105120槽物理与费用复核、逐日购电向量相同、指令时序和账本通过；同时核对输入与计算代码哈希。
- 全项目115项测试通过（30.547秒）；随后增强了非零充放电场景下的未来扰动测试，相关4项再次通过。测试覆盖本槽/未来实际扰动、指令不可重复与不可修改、槽末时间、未发布预测及日终恢复。时间戳审计与代码接口/扰动测试共同支持因果性，不把元数据视为充分证明。

产物目录：`analysis/strict_q2_round2_v1/`。包含 `result.json`、`independent_validation.json`、两份全年JSONL轨迹、`daily_fees.csv`。`result.json`保留计算完成时的待独立验收标记；后续验收以绑定其哈希的 `independent_validation.json` 为准。
