# 第二轮优化：研究审计与实验协议

日期：2026-09-11。状态：Q2的B0—B3、两种Oracle、Q3六组迁移及[门控](Q3_VOI_RESULTS.md)已完成334天回放；Q4迁移等增强待实现。依据 tim 提供的深度研究稿及本地执行代码；研究稿中的外部文献未在本轮逐条核验。

## 审计结论

`src/q2/execution.py` 的 `step` 要求本槽实际总量在槽末结算边界提供，却使用该总量计算本槽充放电。现有结果属于明确声明了同槽观测条件的候选。在严格槽首控制模型下，该动作依赖尚未获得的信息，必须另建基线。10分钟聚合数据不足以证明秒级本地反馈能实现同样动作；槽末可知在新实验中是信息协议，并非本轮新增的测量证据。

现有 Q2 15,438,615.10 元、Q3 13,932,761.59 元及五份候选 Excel 保留，不覆盖。它们不能未经重算作为严格槽首控制费用。旧策略在新实验中统一标记 `legacy_same_slot_candidate`。

`scripts/run_real_q23.py` 的旧 PV 更新控制调用 `replan` 和 `revise_commitment`：既使用当前 SOC，又调整剩余购电合同。因此零点方案与旧 PV 更新方案相差约 183.43 万元，是状态与合同重规划的组合效果，不能单独称为电池反馈收益。新 PV 相对旧 PV 更新减少约 5.12 万元，则是在该候选控制与结算条件下的新预报增量价值。

## 对研究稿的必要修正

- 费用统一为 `plan_cost + adjustment_cost + emergency_cost`，其中 `emergency_cost = sum(5*p*U)`。不得再乘一次 5。
- 残差修正选择“原始残差分位数”，或“偏差 + 中心化残差分位数”；不得把偏差与原始残差分位数直接相加而重复计入偏移。
- 一月开发期的历史回放也必须按当时可用的数据建立残差库，不能用一月末统计量生成一月初的历史决策。一月末选定超参数，二月起冻结；正式期间只允许因果扩充残差样本。
- 新口径费用可能高于旧候选，MPC也不保证省钱。预先指定的充放电使 SOC 按动作确定演化，实际净负荷主要影响应急与富余；需明确滚动时更新了哪些预测或状态，不能预设反馈收益。
- 日终6000、效率解释、退款规则和价格可知性分别作为假设敏感性，不能混入算法收益。0.25%只可作为运行前约定的复杂度取舍参考，不是统计显著性或硬性题目要求。

## 严格因果协议

每槽先根据槽首 SOC、截至当时已发布的预测、已结束槽的实际观测，生成并锁定 `C_t,D_t`。槽结束后提供实际负荷和光伏，仅结算 `U_t,W_t`，不得反向修改动作。

应急购电仍承担槽内剩余电网平衡，其总量在槽末结算；该协议不声称应急量在槽首已知，也不代表详细模拟了秒级电网控制。

每次决策记录决策时间、最新实际观测的槽末时间、预报发布时间和动作适用区间。扰动本槽及未来实际值，不得改变已经生成的动作。Q3仅可在0/6/12/18点按题意调整未执行的合同。

保持各方向效率0.9、母线侧5000 kW、能量1200–10800 kWh、每日初末6000 kWh、无售电和现有计费解释。贪心与MPC均执行终端可达性约束，不允许日末直接覆盖 SOC。一月初始化也使用对应因果协议并保留完整轨迹。
