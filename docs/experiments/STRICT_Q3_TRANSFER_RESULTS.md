因此，保留裕量零点固定为这一组实验的最低费用候选，不将“每次收到新预报就改合同”升级为主策略。这不证明新信息本身有负价值；允许忽略新预报的策略仍能维持零点方案。本轮测到的是具体固定更新算法的效果，下一步应比较预期净收益门控。

## 六组控制如何保持公平

- 有/无裕量两个组，各自的零点固定、旧PV更新、新PV更新使用完全相同的初始购电G。
- 所有策略均用上周同时刻负荷与零点发布的线性积分PV预报制定零点计划；统一使用严格贪心储能控制，不混入小时MPC。
- 旧PV组在6/12/18点按当前SOC与零点PV重新求剩余日购电；新PV组仅在这些时刻换用已经发布的新PV。更新当前合同后，再生成本槽储能动作。
- 裕量沿用Q2一月选中的0.8分位数、scale=1、28日窗口、六个4小时桶、至少7个残差日。只在零点生成一次，全天不变，没有用Q3全年费用重新调参。
- 此次裕量仍来自Q2的负荷lag7/PV lag1净负荷残差，**没有宣称它已经校准Q3预报发布时刻和预测提前量对应的误差**。这是直接迁移实验；Q3专属残差建模应作为后续单独版本。
- 继承已验证的严格Q2一月初始化末态6000，所有策略相同。2月1日至12月31日共334天，每日终端6000、逐日继承计算状态。
- 维持各方向0.9效率、母线侧5000 kW、能量1200—10800、无售电。减少合同退原价并收50%违约费，增加按1.5倍，相对当前合同逐次结算。

## 旧PV对照为何与零点方案相同

旧PV组各尝试1002次重规划，但没有实质合同修改。实质修改阈值为一次更新的增购或减购总量超过1e-5 kWh；数值容差内的变化仍记录在账本，不静默改成零。全年旧PV调整费约0.000008元，表中按分显示0.00。

新协议下储能SOC由已锁定的C/D决定，实际净负荷只改变应急与富余结算；固定预测且没有模型状态扰动时，SOC不会像旧同槽反馈模型那样偏离预定动作对应的路径。因此旧PV重规划没有获得此前约183.43万元的组合收益。这个结果进一步说明，旧候选的“状态/合同重规划收益”不能直接转用到严格槽首模型。

新PV两组各尝试1002次、850次发生实质合同修改。原预测组累计增购616,012.80、减购821,682.39 kWh；裕量组累计增购674,764.87、减购885,327.43 kWh。它们是逐次变更量，不能当作最终净购电量。

裕量固定方案应急343,657.86 kWh、富余3,627,617.09 kWh；裕量新PV方案应急359,587.72 kWh、富余3,472,495.96 kWh。后者富余减少，却没有带来总费下降。

## 代码、验证和产物

新代码：`src/q3/strict_execution.py`、`scripts/run_strict_q3.py`、`scripts/verify_strict_q3.py`。Q3层复用严格Q2执行器，额外保护6/12/18边界、已锁定指令、过去合同与预报发布时间；复用原Q3调整LP和费用函数，未另创一套计费解释。

运行目录为项目根目录，无Git仓库。运行命令：

1. `rtk proxy .venv/bin/python scripts/run_strict_q3.py`
2. `rtk proxy .venv/bin/python scripts/verify_strict_q3.py`
3. `rtk proxy .venv/bin/python -m unittest discover -s tests -q`

125项测试通过（49.473秒），新增测试覆盖实际值扰动不改变合同和储能动作、12点预报变化不改变此前动作、未发布预报拒绝、过去合同/重复更新/已锁定指令保护。

独立复核重算物理方程、每日及逐次费用、修订量、月度汇总、Q2残差裕量、零点计划和三组初始合同一致性。用同样的已验证预测与合同、但全零实际负荷/PV重放全部策略，检查充放电和合同决策完全一致。重算分位数存在约1e-13 kWh算术舍入差异时，先按容差验证保存的裕量，再以原始精度重放，以免把输入舍入差异误判为实际值泄漏；月度费用约4.7e-10元的加法差异按既有1e-5元容差核验。

最终独立验收记录为 `analysis/strict_q3_transfer_v1/independent_validation.json`，绑定结果哈希；`result.json`保留计算完成时的待独立验收标记。目录还包含六份JSONL、冻结协议、每日/月度费用CSV、比较CSV及四个指定日完整轨迹。未重新生成官方Excel。
