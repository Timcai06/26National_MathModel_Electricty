- Gate 0 是**项目自建的阶段验收门**（Gate 0–9 对应 Phase 0–9），不是竞赛官方概念。Gate 0 = Phase 0「数据契约与题意冻结」的放行条件，定义在 `docs/plan.md` Phase 0 条目，证据汇总在 `docs/validation/GATE_STATUS.md`。
- 五条判定：① 365×144 读取正确 ② 附件3 重建 365×4×24 ③ 非预期缺失为零 ④ 输入/模型/输出索引一一映射 ⑤ 日期/时间/功率电量转换有自动化测试。
- ①–③ 已满足（193,152 个数值逐项核对，最大差异 0；附件3 重建 35040 条）；⑤ 部分满足（time_axis 8 项测试，全项目 129 项通过）。**未满足的是第 ④ 条**，这是唯一的硬卡点。
- 第 ④ 条的实质冲突：输入标签 `00:10 … 0:00+1`（按「区间终点」解释 → 覆盖 0:00–24:00，与题面一致）vs 输出模板标签 `0:10–0:20 … 0:00+1–0:10+1`（按字面 → 覆盖 00:10–次日 00:10），**整体偏移 10 分钟**。现采用候选映射 `endpoint-positional-v0.1-candidate`，保留原位置与原标签，未重命名、未循环移位，**属供审阅候选，非官方勘误结论**。
- 最具体的未决点：论文表 1 的「10:00–10:10」在候选映射下取 `slot 60`，而模板同位置显示「10:10–10:20」。另注意格式陷阱：年度页 `AQ1` 写作 `7:0-7:10`（分钟不补零），`EO1` 写作 `0:00-0:10+1`，不能用统一字符串切分。
- 其他「尚缺」：队友生成脚本与版本说明、附件3 转换语义（小时值代表整点还是区间）、观测可用性契约、独立复核记录；误差表漏 1496 条（其中 1460 条在实测覆盖内的午夜目标，应 35004 条而非 33544 条）；质量报告「21:00–次日 05:00 光伏恒为 0」不成立（690 个非零点，最大 10.0125 kW）；文献 4 条中 `chen2019two` 元数据错配必须替换，`shuai2016microgrid` / `morstyn2018using` 查无实据。
- **认知陷阱**：Gate 0 未放行 ≠ 数据不可用 ≠ 工作停摆（项目已在未放行下推进到 4/4 候选）。它表示下游所有结果都携带未冻结的语义前提，只能记「候选完成」，不能记「验收通过」。测试全绿只证明代码符合候选假设，**不证明候选假设符合题意**。
- 2026-09-12 复核：`docs/data/TIME_AXIS_REVIEW.md` 把原单一问题**拆成两个独立问题**——① 时点/时段（功率→电量积分近似，三种假设：左端保持 `P(t)/6`、**右端保持 `P(t+10)/6`（当前候选口径）**、线性插值 `(P(t)+P(t+10))/12`）② 模板覆盖范围（10 分钟偏移）。精确错位证据：附件1 第 62 行 10:10 → 内部 10:00–10:10，而 result1 同位置标签是 10:10–10:20；年度模板 BI1=10:00–10:10、BJ1=10:10–10:20，当前把内部 10:00–10:10 的值按位置写进 **BJ 列**。「防 AI 的坑」传言经官网检索**未获证据**，不写入论文。
